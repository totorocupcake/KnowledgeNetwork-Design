# Sync log

Generated by the KnowledgeNetwork Design System design project.
One-way: design system → this repo → the app.

## 2026-08-09 — the export ships source

No token change, no component change, no new rule. What changed is **what the export
contains**, because the app not looking like the Studio was an export problem rather
than a design one.

The export used to carry tokens, the Tailwind theme, the scrollbar script and prose.
Everything structural had to be re-derived from a description: 23 components existed
here as real source and left as `.prompt.md` files, and the Studio shell — where most
of the product's look actually lives — was not exported at all. `readme.md`'s own
index listed `ui_kits/studio/` and `templates/studio/` rows for files that were never
in the folder, so the instruction was to read something that wasn't there.

Added:

- **`components/<area>/<name>.tsx.txt`** — all 23 components, ported to TypeScript and
  Tailwind classes. Theme moves onto utilities (`bg-paper`, `text-ink-2`,
  `shadow-lift-1`, `rounded-lg`); hover states become `hover:` variants and the
  `useState(hot)` pairs they replaced are gone. Inline styles survive only where
  there is no build-time class — runtime drag geometry, SVG viewBoxes, the drawn
  caret / check / bin marks, `-webkit-line-clamp` stacks, and per-instance domain
  hues — each with a comment saying so. Filenames are kebab-case and carry a `.txt`
  suffix so this project's own compiler cannot mistake a shipped copy for a component
  definition and collide with the original; the exports stay PascalCase. Strip the
  suffix on copy — the export README has the one-liner.
- **`components/wash.ts.txt`** — the shared wash transition as one exported class string,
  plus the domain-hue class maps written as literals so Tailwind's scanner can see
  every class it must generate. Never build those names by template.
- **`studio/studio-app.tsx.txt`, `studio/panes.tsx.txt`, `studio/corpus.ts.txt`** — the Studio, as
  the starting point to refactor the app onto. `corpus.ts` is a typed sample graph
  behind the export names the panes read, so the wiring step is one file.
- **`readme.md` → a Layout section** — the four bands of the shell, the flex ratios
  that ARE the pane composition, the `PANE` / `PANE_BODY` recipes, the four-surface
  depth ladder, and the three rules that get missed when the shell is rebuilt from a
  screenshot (`bg-canopy` full-bleed, `min-w-0` on pane wrappers, `overflow-visible`
  so the legend header is not clipped).

Fixed: the index now lists what is actually in the export, with the paths relative to
it, and says plainly that the specimen cards and the split token sources stay upstream.

## 2026-08-09 — containers on the rail

No new component and no token change. `EdgeEntry` gains four props; `ConnectionsPane`
gains one rule that changes what a container focus can show.

**A container's links are its children's links, rolled up.** The corpus authors typed
links between topics, so a module or a domain has none of its own — and the pane used
to say exactly that and stop ("typed links connect topics only"). It now builds a rail
for any node: an edge joins it when **exactly one end lies inside the focus's subtree**.
Both ends inside is internal wiring and is excluded, or the focus would appear on both
ends of its own entry. The subtree is derived by walking `parent`, so it holds at any
depth — Protocol Stack resolves to 8 neighbours across 10 edges, Networking to 9 and 11.

Rolled-up edges are grouped as **via children**, and each entry names the path from the
focus down to the node that actually holds the link — otherwise the row looks misfiled.
A path deeper than one step keeps its first segment and elides the rest
(`Networking / … / TCP & UDP`, whole path in the tooltip): set inline in a node column a
third of a pane wide, three segments hit `break-word` and come apart mid-word.

- **`EdgeEntry`** — new `fromAnchor` / `toAnchor` (that end is the view's focus node)
  and `fromWithin` / `toWithin` (the ancestry prefix, the slash grammar `DocHeader`
  already uses). The emphasis sits on the **anchor**, so a well of entries opens every
  row on the same bold name — the one at the head of the rail — and reads down a column
  instead of being re-parsed row by row. With a prefix present the bold weight goes to
  the *prefix*, not the node beside it. Never mark both ends; an entry with two anchors
  has no subject. Nodes stay unfilled either way: an entry sits in a well, and filling
  one end raised it off the paper.
- **The rail's head** is `--lift-2` with its domain edge at `--stroke-rule`, and the
  rail visibly leaves its bottom edge as a stub before the first stop. Without it the
  focus read as the first item in the list rather than the thing the list hangs off.
- **Each stop carries a caret** at the row's right edge beside its count, in the same
  20px cell the rail's expand/collapse buttons use, so every caret in the pane falls on
  one vertical axis. It is not on the chip: a caret there reads as belonging to the
  node, not to the row.
- **The rail's totals and its expand/collapse pair sit above the head**, not below it,
  so the rail reads as one line running down out of the focus. The count is
  `N neighbours · M edges` — distinct neighbours, then edges to them; they differ
  whenever one neighbour is reached by more than one relationship.

**`EdgeEntry`'s connector shaft is now SVG.** It was a 3px CSS box, which is the
exact failure `EdgeDash` exists to prevent: down a well of entries each shaft landed
on a different subpixel offset and some read visibly thicker than their neighbours.
It is an SVG rect with `shape-rendering="crispEdges"` now, like every other
hairline-scale bar in the system.

**No new icon was added.** The rail's head caret, each stop's caret and the
*expand all* / *collapse all* pair are all the house disclosure mark — the rotated
square `TreeRow` draws as `caretStyle` — with the pair being **two of it stacked**,
down for expand and up for collapse. An earlier pass drew SVG chevrons for these;
that is out. The drawn vocabulary stays at exactly two marks (`BinMark` and the
caret), and `▾`/`▸` have been **dropped from the glyph vocabulary** — they named a
disclosure the drawn caret already owns, and nothing in the system set them. `caretStyle` does not cross the `window` boundary, so the pane repeats the
recipe rather than importing it — with `caretStyle`'s border **longhands**, not the
`border` shorthand plus `borderTop: 'none'`: React re-sets the shorthand on a colour
change without re-setting the switched-off sides, and the caret fills in to a diamond
on first hover. One geometry note if you rebuild the pair: the mark is a corner, so
its ink sits low in the box pointing down and equally high pointing up — both
directions take `translate(-1px, -1px)`, which resolves in each one's own rotated
frame to the correction that direction needs. Mirroring the nudge doubles the error
and the two marks sit 3px apart.

For the app: `SYMMETRIC` (currently just `see_also`) is still a hand-kept map in the
pane rather than corpus data, and `DOMHUE`/`EDGEHUE` are duplicated between the pane
and `EdgeEntry`. Both are worth folding into the corpus and the tokens respectively.

## 2026-08-08 — the connections rail

One new component and one replaced pane. Nothing in `tokens/` changed.

- **`EdgeEntry`** (area `graph`) — one relationship, drawn: two nodes and the typed
  edge between them. The relation is what gets the emphasis — body weight over a
  3px rule in the edge's own colour — and the two nodes recede to caption weight
  with a domain border and no fill. An entry is a sentence, and both ends are
  usually already known from whatever it sits inside; the relation is the only new
  word. The arrowhead goes on the end that *receives*, and `direction="both"`
  covers a symmetric relation.

  Three things in it are load-bearing and easy to undo by accident. The connector
  column takes its width first and the nodes share what is left, because the
  connector carries the string the entry exists for. The line is that column's only
  in-flow child, with the label positioned above it — stacked in flow, the label
  pushed the line down and a two-line node left the arrowhead at its foot instead
  of its middle. And clearance around the label is margin, not padding: padding
  lives inside the box, so a label wider than its column still overran the node
  beside it.

**The connections diagram is gone.** `ConnectionsPane` was a radial dial ported from
`PlexPanel.tsx` — SVG rings, one per relation type, neighbours as unlabelled circles
on an arc. It does not survive density: past about 24 neighbours the geometry solves
to a 9,000-unit dial that shows nothing at a legible scale, and the circles never
carried names at any count.

It is now a **rail**: the focus at the head, one row per neighbour down a vertical
line, ordered by how many edges each shares. Opening a stop lists its relationships
in full as `EdgeEntry` rows, split into the ones authored on the focus itself and the
ones it inherits through its children — "this depends on X" and "something inside
this depends on X" are different claims. A hundred neighbours is a longer rail, not a
denser one, and nothing overlaps at any count because nothing shares a row.

For the app, two behaviours worth keeping: open stops are a **set**, not a single id
— comparing two neighbours means having both open, and a rail that closed one to open
another made you hold the first in your head. And `see_also` is treated as symmetric,
because its authored direction is an artifact of which document was written first.

The rail also means `readme.md`'s drawn-graphics rule now has **no exception but
`BinMark`**. Nothing else in the system is drawn.

## 2026-08-07 — the versioned subgroup

Four components, one new area. Nothing in `tokens/` changed: all of this is built
from the existing palette, elevation and motion.

- **`VersionedGroup`** (new area `group`) — a nested subgroup that keeps several
  versions of itself and shows exactly one. The picker names the live version and
  opens the list of the others; a version is added, renamed and deleted from that
  menu. Open it is the recessed well, folded it is a node again at `--lift-2` with
  the well tint stacked behind. Editing is in place on a single click — title,
  version name, description. It moves by its own background, resizes by its edges
  (double-click an edge to give that dimension back), and its contents are a
  `NodeChain`.
- **`NodeChain`** (new) — the sequence a chain of nodes forms, and the owner of
  their order: drag-to-reorder constrained to its axis, an arrow in every gap, and
  derived step numbering (`2.` hands out `2.1`, `2.2`). Reordering could not live
  in the nodes — a chip that dragged itself would need its siblings' sizes and order
  to know where it had landed.
- **`NodeArrow`** (new) — the arrow between two nodes. Sequence, not a typed
  relation: no `--edge-*` hue and no label, because the order belongs to the
  container rather than the corpus. Acorn by default; dashed means conditional.
- **`NodeChip`** — gains `index` (a derived step number, mono at `--text-3`),
  `mark="border"` (the domain hue as a 1.5px edge instead of a dot, for a node
  standing on its own), `onDelete` (a ✕ that arrives with hover or focus), and
  edge-drag sizing whose floor is the text itself.

Two rules this round produced, both now in `readme.md` and `SKILL.md`:

- **A destructive control wears berry at rest, not on hover.** Hover is a one-step
  wash of an element's own family and never a hue change — and a warning that
  arrives only under the pointer arrives too late.
- **Everything that recedes runs on `window.PKT_SB.LEAVE`**, and anything hidden by
  opacity also leaves the tab order.

One ownership rule for the app to get right: **nodes belong to the version, not to
the group.** The group renders whatever children it is given for the live version, so
the app must key them by version id — hold one list per group and a new version
inherits the previous one's nodes, which is the one thing versioning exists to avoid.

Two acts, two different answers, worth keeping straight when the app implements
them: deleting a version **asks** (it destroys nodes you cannot see), ungrouping a
multi-version group is **refused** (it would silently discard all but one version,
and no wording makes approving that sensible).

## 2026-08-05 — caps tracking

- `scrollbars.js`: releasing a click in the gutter no longer drops the bar to
  `data-sb=on` for a frame before the next pointermove restores `near` — the
  visible blink on click-to-scroll. The bar holds `near` while the pointer is
  still in the gutter.

- New token `--ls-caps: 0.12em` (Tailwind `--tracking-caps`). **Every all-caps
  string in the system carries it** — via tags, document eyebrows, toolbar group
  labels, axis labels. `--ls-eyebrow` is now an alias of it, so anything already
  using the eyebrow token picks the new value up. Was 0.08em; caps at that
  tracking read as one solid block at 11–12px.
- `TrailChip`'s via tag (`MAP`, `TREE`, `LNK`) was set at default tracking and
  now carries `--ls-caps`.

## 2026-08-05 — initial export

First full export. Contains 8 token files flattened into two stylesheets, a
Tailwind v4 theme, the scrollbar script, and the contracts for 19 components
across 5 areas (chrome, sidebar, graph, nav, doc).

Recent design system changes carried in this export:

- `--border-hair` raised to 17% bark and `--border-rule` to 25% (from 9% / 15%
  originally). At the original alphas the dividers all but vanished on paper.
- `--ring-linked` thinned to 1.5px, and it now sits over the chip's own
  `--lift-1` rather than replacing it. A chip that swaps elevation for a 2px
  ring reads as *selected*, which is a different claim.
- Relation dashes are drawn as an SVG `rect` with `shape-rendering="crispEdges"`
  (`EdgeDash`). As 3px CSS boxes they landed on different subpixel offsets down
  a list and some read visibly thicker than their neighbours.
- Scrollbar arrowheads stroke at `#c8bfaf` — `--bark-300` nudged 30% toward
  `--bark-400`, hard-coded because a `data:` URL can't read a custom property.
  Re-derive it if either bark step ever changes.
